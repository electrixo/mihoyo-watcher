## 1. 项目背景（30 秒）

一个跑在 GitHub Actions 上的米游社福利监测工具，每天做三件事：

| 轮次 | 做什么 |
|---|---|
| 抓码 | 搜索「兑换码/前瞻/礼包」等关键词，识别并推送新兑换码 |
| 日报 | 抓三款游戏（原神 / 星穹铁道 / 绝区零）的公告、活动、资讯 + 码，合成一条日报 |
| 签到 | 可选，默认关闭（`CHECKIN_ENABLED` 未设置时不运行） |

关键点：**真正送达时间 = 触发时刻 + 调度延迟**。GitHub 的定时器会延迟数小时，
这个延迟不可控，是下文问题的根源。所以设计时应先定「想几点收到」，再用偏移反推触发。

## 3. 问题

### 3.1 日报永远差一口气

米游社资讯发布高度集中在整点（星铁 17 条样本）：

| 发布时段 | 占比 |
|---|---|
| 12:00 | 53% |
| 18:00 | 24% |
| 13:00 / 14:00 / 19:00 | 少量 |

日报到达中位 **09:47**，整个窗口 08:22–12:49 压在 12:00 之前，导致**当天 12:00 发布的
53% 资讯抓不到**，要等第二天才带上。证据：11-24 12:49 到（唯一赶上）、11-25 11:33 到（差 27 分钟）、
11-26 10:58 到（差 1 小时）。

### 3.2 签到兜底会跨天

14:10 触发的兜底轮到达 22:27 – 次日 01:56，**有 3 次跨过午夜**。跨天后脚本里的「今天」
就变成了次日，等于当天的漏签补不回来。

---

## 4. 原因

```
到达时刻 = 触发时刻 + 延迟（4h07 ~ 11h46，方差 4 小时以上）
```

触发是唯一可控变量，延迟是黑盒。要让日报**保证**覆盖 12:00，触发必须晚于：

```
12:00 − 最小延迟(4h07) = 07:53 BJT
```

现在的 04:15 差得很远。签到兜底同理：要保证当天内到达，触发必须早于 `23:59 − 11h46 = 12:13`。

## 5. 日报方案对比（按 7 个日报样本回算）

| 触发（BJT） | 到达窗口 | 中位到达 | 越过 12:00 | 最晚到达 |
|---|---|---|---|---|
| 04:15（现在） | 08:22 – 12:49 | 09:47 | 1/7（14%） | 12:49 |
| 06:30 | 10:37 – 15:04 | 12:02 | 4/7（57%） | 15:04 |
| **08:10（选定）** | **12:17 – 16:44** | **13:42** | **7/7（100%）** | 16:44 |

## 6. 为什么选 08:10

- 越过了 07:53 这条硬线，7/7 全覆盖；
- 中位 13:42 到，最晚 16:44，仍在「当天」；
- 08:05 也够，08:10 多给 12:00 的帖子留 5 分钟进索引，并避开整点高峰。

换算 UTC：**08:10 BJT = `10 0`（UTC 00:10）**。
签到兜底定 **11:05 BJT = `5 3`（UTC 03:05）**，到达 19:22–22:51，全部当天。

## 7. 具体改动（6 个文件）

### 7.1 `.github/workflows/watch.yml`（6 处）

**① 头部说明**
```diff
-#   04:15 BJT 触发（UTC 20:15 前一天）→ 完整日报（资讯+码）+ 签到
-#   14:10 BJT 触发（UTC 06:10）       → 签到兜底（幂等）
+#   08:10 BJT 触发（UTC 00:10）→ 完整日报（资讯+码）+ 签到
+#   11:05 BJT 触发（UTC 03:05）→ 签到兜底（幂等）
```
同时把文件开头的「2026-11-19 改版」段落替换为「2026-11-26 按到达时刻反推」。

**② cron 声明**
```diff
-    - cron: "15 20 * * *"         # BJT 04:15 触发 → 完整日报 + 签到
-    - cron: "10 6 * * *"          # BJT 14:10 触发 → 签到兜底
+    - cron: "10 0 * * *"          # BJT 08:10 → 到达 12:17–16:44，完整日报 + 签到
+    - cron: "5 3 * * *"           # BJT 11:05 → 到达 19:22–22:51，签到兜底
```

**③ `watch` job 的 `if`**
```diff
-      github.event.schedule == '15 20 * * *' ||
+      github.event.schedule == '10 0 * * *' ||
```

**④ `checkin` job 的 `if`**
```diff
-        github.event.schedule == '15 20 * * *' ||
-        github.event.schedule == '10 6 * * *'
+        github.event.schedule == '10 0 * * *' ||
+        github.event.schedule == '5 3 * * *'
```

1. **跑测试**：`python -m unittest tests.test_watch_mihoyo tests.test_mihoyo_codes tests.test_mihoyo_comments tests.test_workflow`，应全绿（当前 89 个）。

   `触发 event=schedule schedule=10 0 * * *`。
3. **观察 3 天**：日报到达是否落在 12:17–16:44，正文是否带上了当天 12:00 发布的帖子；
   签到兜底是否全部在当天 23:59 前到达。
4. 第一天如果有一轮没出现，先别下结论——改 cron 后 GitHub 偶尔有一次过渡期丢失。

| 不要动 | 原因 |
